# Parcelable-Creator-Erased-Generics

> [!info] Level 3 — real code
> A real Kotlin `Parcelable.Creator<AccountDevice>`: the generic type survives only in a class `Signature`, methods carry erased `Object` types, and array covariance lets `newArray` return a typed array as `Object[]`.

## Context

`AccountDevice` is PressReader's model for one registered device on a user account (the device-management screen). Android rebuilds it from a `Parcel` through a static `CREATOR` object; in Kotlin that's typically generated by `@Parcelize`, and here it compiled into the nested class `AccountDevice$a`. Everything about types in this class is visible in under 40 lines.

## Notes

- **The generic argument lives only in `Signature`.** The `.implements` line says just `Parcelable$Creator`; `<AccountDevice>` is in the annotation. This is [[Generics-Erasure-And-Signature-Annotations]]'s step 3 on real code — and a reminder that R8 kept `Signature` attributes in this build, which isn't guaranteed.
- **No bridge methods.** A Kotlin/Java source override returning `AccountDevice` would produce a typed method plus a `bridge synthetic` one returning `Object` (see [[Overloading-And-Bridge-Methods]]). Here only the erased versions exist — most likely R8 merged each bridge into its target, since nothing called the typed version directly. Don't expect release builds to keep the source's precise return types.
- **Array covariance.** `new-array p1, p1, [L...AccountDevice;` creates a real `AccountDevice[]` but the method returns `[Ljava/lang/Object;`. Java arrays are covariant (`AccountDevice[]` *is an* `Object[]`), so no cast is needed. Also note the parameter register `p1` reused for the result: the size is dead after `new-array`.
- **Kotlin's null check.** `Lkotlin/jvm/internal/l;->f(Object, String)` with the parameter name `"parcel"` is the obfuscated `Intrinsics.checkNotNullParameter`. The string argument hands you the real parameter name for free — a reliable Kotlin de-obfuscation trick.
- **Constructor shape from the descriptor alone**: `(Ljava/lang/String;Ljava/lang/String;Ljava/lang/String;JJ)V` gives the field order of `AccountDevice` (three strings, then two longs — plausibly id/name/model and two timestamps) without opening the class. The `/range` call itself is analysed in [[Invoke-Range-For-Many-Arguments]].
